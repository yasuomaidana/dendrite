The first level is Task-Level Recursion (Propose–Probe–Compose), which optimizes execution for the current assignment. When an unseen task arrives, the agent first executes the task once using its baseline harness to generate a reference execution trace. The purpose of this baseline run is not to verify final output correctness, but to observe behavioral friction—such as where the agent hesitated, which tool invocations failed, or where context overflowed. Next, in the Propose phase, an improver model (HARNESS2_IMPROVER_MODEL, which defaults to the executor model or can be configured to Vertex Gemini or Claude) drafts two distinct classes of candidate harness modifications: an invariant candidate targeting universal agentic flaws (planning, context hygiene, delegation) and a domain-specific candidate targeting domain procedures and verification rules. In the Probe phase, the solver agent (HARNESS2_SOLVER_MODEL) re-executes the exact same task under matched environmental conditions using each candidate harness. Finally, in the Compose phase, a composer module performs a behavioral contrast across the reference and probe traces, merging only those file edits substantiated by empirical execution improvements into a composed successor harness.The second level is Harnessing-Level Recursion (Cross-Task Experience Library), which governs how harness optimization transfers across assignments. Rather than permanently mutating the base agent into a brittle, overfitted configuration, each new task begins from the clean base harness. However, after each task completes, an experience reflector updates a persistent improvement harness—a cross-task library of adopted harnesses and evidence-backed lessons. Consequently, while the solver agent resets per task, the improver's meta-harness compounds knowledge over time, shaping future Propose–Probe–Compose cycles.Operators scale this dual-loop process via the --k recursion budget flag across two topologies: Parallel recursion (--mode parallel), which probes $k$ general and $k$ domain-specific candidates simultaneously and composes $k$ refinements from shared evidence ("exploring wider"), and Sequential recursion (--mode sequential), which chains the refined harness through $k$ successive Propose–Probe–Compose iterations ("refining deeper").Empirical Performance, Failure Modes, and Trade-Offs Against yasuomaidana/dendriteGoogle evaluated Harness² across three multi-domain benchmarks—LAB (legal work, requiring Pandoc and Poppler), WorkBuddy-Bench (office, web, and code subsets, requiring Docker), and JobBench (professional assignments)—testing four model-harness configurations pairing GLM-5 and Gemini 3.5 Flash as executors with Vertex Gemini or Claude as improvers. Where Harness² operates during or after execution to tune the agent's scaffolding, EGM operates before code generation and after implementation to enforce strict Spec-Driven Development (SDD) through deliberate context asymmetry.The foundational architectural problem EGM solves is single-agent /plan blind spots caused by conversational sycophancy and sunk-cost bias. In Pillar 6 of yasuomaidana/dendrite, if a single long-running Claude or AGY session both drafts a ticket's specification (/plan) and reviews its own readiness for implementation, the model accumulates implicit assumptions from the chat history that never get written into the specification document. When that spec is later handed off to a worker agent inside pkg/sandbox or a local OxiLLaMa/Ollama runner, the worker fails because critical cross-crate boundaries (e.g., between dendrite-control in Go and dendrite-core-rs / dendrite-git-rs in Rust) were left implicit.EGM eliminates this failure mode by splitting cognition into two strictly isolated roles:The Elephant (Long-Horizon Stateful Architect): A persistent, context-rich primary session (backed by dendrite-rag-rs and Gentle-AI/Engram) that retains full project memory, architectural vision, and prior decisions. The Elephant conducts Socratic interviews with you, debates trade-offs, and drafts the formal specification section by section—writing zero production code.The Goldfish (Stateless Zero-Context Adversarial Swarm): Isolated, ephemeral subagents spawned with a completely blank context window. A Goldfish subagent is permitted to read only the draft specification file (concepts_brief.md or design_draft.md), the repository's document standards (resources/document_standards/), and the live source code—with zero access to the conversation transcript that produced the design. Because the Goldfish remembers nothing of the prior negotiations, any unstated assumption, missing Rust/Go FFI or IPC contract, or hallucinated file path in the spec is immediately exposed.Crucially, EGM enforces a hard architectural safety check: Goldfish reviews require true fresh-context subagent delegation. If the host agent harness cannot spawn an isolated subagent context, EGM halts the review rather than running a biased check inside the existing session.Cross-Harness Plugin Architecture for Claude Code and Antigravity CLIUnlike Harness², EGM was built as a unified, zero-fork cross-harness plugin adhering to the portable Agent Plugins 1.0.0 specification (plugin.json).
