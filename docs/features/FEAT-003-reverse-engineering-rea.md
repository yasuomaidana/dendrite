# FEAT-003: Binary & Application Reverse Engineering Suite (REA)

## 1. User Story & Business Objective
As a security researcher and systems developer, I need an automated, evidence-backed reverse engineering environment that allows autonomous AI agents to decompile, analyze, and safely recreate functionality from third-party binaries, legacy shared objects, and packaged applications without hallucinating or leaking proprietary bytecode.

---

## 2. Technical Boundaries & Specifications

1. **Tooling Integration**:
   - macOS Host: REA CLI & MCP server (`rea-agents mcp`) paired with Hopper Disassembler for Mach-O, Swift/ObjC metadata, and local Chrome DevTools Protocol.
   - Remote Linux Worker: Containerized headless Ghidra (`analyzeHeadless`), Rizin, and Binwalk on Debian/Azure.
2. **3-Stage Methodology Contract**:
   - **Decompile**: Recover disassembly, pseudocode, and symbol definitions.
   - **Understand**: Trace control flows, isolates constants/algorithms.
   - **Recreate**: Synthesize clean, idiomatic code with unit test vectors.
3. **Docs-as-Code Gate**:
   - Agents are barred from directly generating implementation pull requests before drafting an Architecture Decision Record (`docs/architecture/decisions/ADR-XXX.md`) and securing human sign-off.

---

## 3. Acceptance Criteria & Verification Matrix

- [x] **AC-1**: REA MCP server returns bounded evidence bundles rather than monolithic assembly dumps, capping single responses to $< 4,000$ tokens.
- [x] **AC-2**: macOS REA commands execute locally on Apple Silicon without transmitting binary code outside the private host.
- [x] **AC-3**: Untrusted Linux binaries execute exclusively inside the sandboxed container with `cap_drop: [ALL]`.
- [x] **AC-4**: ADR documents generated by REA workflows validate against the project YAML frontmatter schema.

---

## 4. Definition of Done (DoD) & Persistence Verification

- **Automated Tests**: Integration tests verify that disassembler outputs produce valid pseudo-C/Rust AST representations.
- **Persistent Layer Verification**: Decompilation project caches and symbol tables stored in volume mounts verify consistency across restarts.
